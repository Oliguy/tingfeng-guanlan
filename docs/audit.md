# 2.0.0 分层审计与验证

审计日期：2026-10-09。目标是保留六栏目及其业务语义，让界面、功能和数据可以分别维护、部署和连接。

## 职责调整

原实现依赖安装路径发现、固定工作区配置和本机业务包，页面入口与业务分派绑定。现在界面包只包含页面、图表、传输及桌面窗口适配；应用包负责认证、API、用例和外部任务适配；数据包负责配置、SQL、数据库合同和仓储。纯计算放在 domain 包，属于功能层。

仓储不导入应用或界面，纯计算不导入仓储，界面不导入数据或应用。应用中的训练 SQL 已移入命名仓储语句。阅读入口不导入 StockOperator，不扫描其他项目安装目录。继承代码中未被六栏目使用的旧独立 HTML 导出/自动更新脚本不进入便携发行；数据生产仍由显式提供者执行。

数据库仍采用既有 SQLite 消费结构，新增角色、字段、类型亲和性、主键、版本和单位合同。原市场、分类和计算源只读；新训练及题材状态有独立写入边界。未对真实原库做复制、迁移、索引、修复或更新。

跨电脑访问使用认证 API。浏览器、独立本机连接入口、Python 客户端共用请求合同；数据库文件只由数据宿主本地访问。更新请求保留原 request_id 和提供者任务身份，网络回执不明时不自动重提。

## 已验证范围

- Windows、Python 3.14 下，197 项测试和 60 个子测试通过：既有计算/训练回归、分层边界、只读保护、认证、CSRF、代理连接和未知回执恢复。
- 合成数据上的训练重复请求、服务重建后恢复，以及题材预览、重复保存、归档和恢复通过；真实用户训练库未用于写入测试。
- 从独立构建目录生成 wheel，在隔离虚拟环境中安装，从源码目录外以 Python 隔离模式启动；真实数据的九类库结构检查通过。
- 原版与便携版对同一原址数据的 19 组查询逐字段核对一致。仅排除响应计时和进程随机会话编号；业务日期、数值、指标、分组和来源状态保留比较。18 组返回数据，1 组返回两版相同的周线缺失错误。原库及已有 WAL 的大小和修改时间前后未变。
- 浏览器通过客户端代理打开首页、行业、ETF、题材、异动、龙头详情和训练；行业、ETF 图表有数据。模拟训练经登录后保存，刷新恢复。源码与独立安装包的六栏目各在九种宽度下完成 54 个布局样本检查，无重复导航、页面横向溢出或设置丢失。
- 原址查询中，行业/题材摘要约 0.1 秒，ETF 摘要约 0.4 秒，异动日查询约 3.5 秒，龙头约 20.7 秒。这是该次本机测量，不能当作跨电脑性能承诺。

私有验收材料包含来源路径与实际行情，保留在本地项目档案，不进入公开仓库。

## 已知边界

- 抽查 ETF 的周线仍提示“周线尚未生成或已修订”。这是原有来源状态，浏览与本次审计不会重算原库。
- 实测使用本机的独立进程和客户端代理；第二台物理电脑、实际 SSH 链路及公网 HTTPS 代理尚未实测。
- 本轮未触发真实采集、重算或更新任务；提供者转发与请求身份经过隔离测试，现场更新取决于原数据生产服务。
- Windows 原生窗口适配已移入界面包，但 2.0 的可见窗口、任务栏及重复打开尚未人工验收。浏览器入口已验收；原 1.2 原生入口与用户记录继续保留。
- Linux/macOS 和 Python 3.12 的现场验收不由本机结果替代。仓库包含 Windows/Ubuntu、Python 3.12/3.14 测试矩阵，运行结果以 GitHub Actions 为准。
- 当前为可信个人工作区，共享访问令牌的客户端共享状态和权限；没有多租户账户隔离。

## 重现

```sh
python -m pip install '.[test]'
python -m pytest -q
python tools/check_public.py
```

Windows 安装 Edge 和 Playwright 后，可对安装包运行无数据的界面检查：

```sh
python -m pip install playwright
python tools/check_ui.py --source --output ../guanlan-ui-check
```

它将 API 响应替换为来源不可用，验证导航和设置在失败状态下仍可操作；不会读写市场数据。源码/实际安装包应各检查一次。
