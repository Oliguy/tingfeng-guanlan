# 数据库整合与指数采集（2.1）

行业相关的五个库收敛为三个。数据库由数据宿主维护，其他电脑运行界面与功能，通过认证 API 连接宿主；连接方式沿用《跨电脑部署》。

| 数据库 | 职责 | 访问方式 |
|---|---|---|
| business.sqlite | 股票身份、财报与经营事实、自有30行业和子行业目录、分类证据 | 听风阅读只读，资料更新由所属生产者管理 |
| collections/catalog.sqlite | 自定义题材、成员与标签修订、操作回执 | 题材管理功能写入 |
| collections/results.sqlite | 行业、子行业、题材统一发布结果和共享指标引用 | 发布者写入，界面只读 |

行情、ETF、历史ST状态、辅助证据、交易日历与训练用户状态各有职责，仍独立存放。三个行业库无需合为一个文件，避免混合事实、用户状态和计算结果。数据不随程序上传 GitHub。

旧 `indices.sqlite` 和 `industry_classification_model.sqlite` 已退出当前读取与生产合同。2.1 不要求 `paths.industry_db`；旧配置中的该字段仅忽略以便升级，建议删除。行业读取仅使用 `collection_root/results.sqlite`，不存在时明确报告，不回退旧库。旧 `run_id` 查询会提示退役；重新打开行业页选择当前发布，成员详情使用 `publication_id` 固定版本。

## 四指数更新

在数据宿主执行原 StockOperator 的 `market_sync` 任务，个股、复权和四指数属于同一任务。个股来源保持原配置；指数通过独立 AXDATA SDK 环境调用 `index_kline_tdx`：

| 指数 | AXDATA代码 | 保留的市场库标识 |
|---|---|---|
| 上证指数 | 000001.SH | sse_index |
| 创业板指 | 399006.SZ | chinext_index |
| 科创综指 | 000680.SH | star_market_composite |
| 科创50 | 000688.SH | star50_index |

宿主在运行配置的 `external_sources.axdata_project` 指向已安装 AXDATA；也可通过 `STOCK_OPERATOR_AXDATA_PYTHON` 指定其解释器。AXDATA 环境须能访问通达信来源。SDK不嵌入便携听风包，客户端电脑无需安装 AXDATA。

采集只采用现有交易日历确认的收盘日，16:00（上海时间）前不提交当天日线。即使个股已新，指数仍单独检查。按历史末日向前重叠7日补齐，校验四项身份、OHLC、成交数据和全部应有交易日，再单事务提交。单次缺口超过800自然日时要求分段补齐，不截断后冒称完整。

指数按原始点位保存，无个股复权。`market_source_contracts` 逐日保存来源、证券身份、单位、响应哈希、请求编号和取得时点；成交额为元，成交量保留 AXDATA/TDX 原生单位，不擅自标为股或手。旧历史保留其原来源口径，不能假设全历史单位一致。指南针活跃市值仍由博采归藏生产，市场指数采集不会更新它。

来源请求最多等待90秒。超时、断网、缺少一个指数或某个交易日时，保留既有指数，任务报告指数分支阻断。已提交个股保持有效；沿原任务编号查看结果，待来源恢复后明确重试，不把失败显示成整体成功。

## ETF映射

ETF 当前映射使用同一自有30行业目录 `I01..I30`，不再依赖外部旧分类树。跟踪指数的来源代码、名称、目录版本、资料时间和股票实际经营分类证据保存在映射发布版本中。股票证据只采用当前 `source_supported` / `verified` 且 `actual` 的关系，程序通过不升级事实质量。

行业词义清楚的跟踪指数可映射；基金名称本身不足以定类。披露持仓只能提供已观察的权重下界，未知权重不补齐，也不把前十大持仓归一化成全部投资纯度。港股、美股不会补零冒充A股；同码不同来源的指数保持不同身份。

宽基、跨境、债券、货币、商品等不强配行业。通信、新能源、科技等跨多个自有行业的范围，以及行业词义和持仓冲突，保留待确认。映射清晰并不意味着所有ETF都有唯一行业；待确认需要新增来源证据或有依据的规则复核。

分类更新优先复用已有资料，不启动全市场新采集或模型调用。全量映射单事务发布，当前ETF主表和分组与同一版本一致；旧关系保留历史，关注ETF与行情不删除。映射从当前知识日期生效，不把新结论回填到旧日期。

宿主的听风ETF服务可在 `data.etf.refresh_monthly` 请求中传入 `{"classification_only": true}`，仅重映射已有证据，跳过新披露采集与历史领涨选择。它仍使用原任务库、写入锁和执行许可；便携客户端须配置所属更新提供者。失败后按原任务编号明确重试，不能绕过任务保护直接写库。

新目录对应的分组合成行情从当前生效日积累；在样本不足时，分组强弱可能显示不可用。个体ETF原有行情保持可读，不能通过回填当前分类伪造历史强弱。

## 升级与核验

1. 安装2.1程序，更新配置，保留三个行业库与ETF/行情库原址。
2. `guanlan doctor --config <配置文件>` 检查当前合同；不自动迁移、修复或取数。兼容只证明结构满足消费合同，不证明行情新鲜。
3. 打开行业、题材、ETF和成员详情，确认当前发布日期、股票行情和关注列表。
4. 由所属生产者执行行情同步和ETF映射。完成后核对四指数的目标日期及映射发布版本；来源失败按任务反馈处理。
5. 确认所有当前入口已脱离旧库后再做明确范围清理。程序安装不会自动删除数据库；不得根据名称泛删旧文件、备份或其他资料。
