# 数据系统归集与连接

2.2 支持一个总数据目录下的四个系统组。数据宿主维护 `storage_layout.v1.json`；界面与应用功能只读取这份路径合同，不包含真实数据库。没有该清单的旧配置及演示数据继续使用原布局。

```text
data/
  storage_layout.v1.json
  01_market/       行情、市场指数及活跃市值、证券状态与限价支持
  02_industry/     经营事实、题材修订、统一发布结果、ETF
  03_indicators/   知行标签与策略、指标底座、运行状态、界面投影
  04_user_state/   K线训练记录
```

业务存储共13项：10个SQLite文件、3个Parquet数据集。行业三个核心库分别保存经营事实、题材修订、发布结果；通过股票代码、期间、已知时间、修订和发布编号关联。ETF通过行业代码和映射版本扩展行业系统。

两项合并按表划分写入职责：证券状态库接纳限价与补充行情回执；知行策略库接纳标签表。原表名、历史内容和方法版本保留。同文件使用SQLite事务锁，各模块仅写自己的表。不同文件之间采用逻辑关系，不设置跨文件外键。

技术底座保留MACD、KDJ、BOLL等完整指标；知行Z底座是重复Z字段的权威来源，技术底座中的同名列保留作兼容投影。听风指标缓存供界面快速读取，不替代完整底座。证券逐日状态与历史来源均保留。删除退役库不会替代为虚构历史。

在数据宿主上配置：

```json
{
  "schema_version": "guanlan.config.v1",
  "paths": {
    "storage_root": "D:/GuanlanData",
    "state_root": "D:/GuanlanData/04_user_state",
    "training_db": "D:/GuanlanData/04_user_state/training/tingfeng_kline_training.sqlite"
  },
  "server": {"host": "127.0.0.1", "port": 18738, "token_env": "GUANLAN_ACCESS_TOKEN"},
  "provider": {"enabled": false}
}
```

`storage_root`定位总目录。启用清单时，`market_root`默认为其中的`01_market`；行业、支持、日历和缓存位置按清单解析。`state_root`必须与`market_root`互不包含，业务源不得置于可写用户状态中。接入已有训练记录须明确填写`training_db`；省略时创建新的`state_root/training.sqlite`，不会自动搬迁用户记录。

```sh
guanlan doctor --config guanlan.json
guanlan serve --config guanlan.json
```

归集后的题材目录属于数据宿主；便携端需配置已有更新提供者才能向宿主提交编辑，`provider.enabled=false`时只读取该共享目录。训练仍保存于显式用户状态中。

其他电脑继续使用认证API或`guanlan connect`，无需数据库文件。详见[部署与连接](deployment.md)。不要将SQLite目录作为多人可写网络盘。路径清单中的历史地址映射只用来读取已登记的旧引用，不创建旧数据库，也不修改历史来源摘要。源码不执行生产迁移：搬迁必须由数据宿主停止相关写入后实施，并核对源表内容、文件身份和阶段收据。

如果迁移中断，查看宿主的迁移收据，从已完成的事务或文件移动继续；不要复制整库、覆盖未知目标或同时启用两套写入。现有备份及原始资料归档不属于这次业务库移动范围，保留其已有引用。
